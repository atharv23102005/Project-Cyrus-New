C++ Concepts, OWASP LLM Guardrails & Architecture Q&A

Q1 Why compile CYRUS in C++ instead of Python?
Answer: Latency and throughput! LLM security inspection runs on every single incoming user prompt. Python GIL lock and garbage collection introduce millisecond delays. C++ offers sub-50 microsecond execution latency, zero heap allocation pass-by-reference scanning, and multi-threaded scaling!
Q2 What is Direct vs Indirect Prompt Injection?
Answer:
  • Direct Injection (Jailbreaking): End user crafts instructions to break system prompt boundaries (e.g. DAN 6.0).
  • Indirect Injection: Malicious prompt instructions hidden inside external data (PDFs, web pages fetched via RAG) that hijack the LLM during processing.
Q3 How does CYRUS prevent ReDoS (Regular Expression Denial of Service)?
Answer: ReDoS occurs when regex engines backtrack exponentially on nested repetition patterns (e.g. (a+)+b). CYRUS compiles regex patterns once during initialization, avoids nested quantifiers, and uses anchored search bounds.
Q4 What C++ Memory Management principles were used?
Answer:
  • RAII: Regex objects are bound to CyrusEngine lifecycle.
  • Const References: const std::string& prevents string copies on every scan pass.
  • Scoped Enums: enum class SeverityLevel prevents global scope collisions.
